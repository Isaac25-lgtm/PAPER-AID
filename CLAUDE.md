# PaperAid — working rules for coding agents

The authoritative product spec is `PaperAid_Master_Product_Architecture_and_Implementation_Specification.md`. Most of its per-requirement "Implementation / Guardrails / Acceptance" paragraphs are repeated boilerplate. Read the section intros, the "Required outcomes" lists and Appendices A–K instead. Owner decisions that refine the spec are in `docs/decisions.md`. They win over the spec where the two differ.

## Product in one line
Researchers and students (owner decision 2026-10-02: never university students only) upload a paper or start a piece of work, and later download a finished result. PaperAid is job-based, not a chatbot. Positioning: "paper-ready" (clarity, correct formatting, reviewable output). Never market it as beating AI detectors.

## Fixed architecture
- AI runs on Gemini through Vertex AI (owner decision 2026-10-07; read `docs/Gemini_Vertex_Handoff_20261007.md`). Vertex inference, quota and billing are in project `paperaid`, location `global` (`VERTEX_PROJECT`, `VERTEX_LOCATION`; never `GOOGLE_CLOUD_PROJECT`); every application resource stays in `paperaid-ca172` (`GCP_PROJECT`, Firebase pinned to it). Only the worker's service account calls Vertex, with its own credentials (ADC); no key file.
- React + TypeScript + Vite (`web/`, dev server on **port 5000**), hosted on Firebase Hosting.
- Firebase Auth, Firestore (metadata only), Storage (files), App Check.
- One Python FastAPI backend (`backend/`), deployed to Cloud Run as two services from one image: a public `api` and an internal `worker`. Background work runs through Cloud Tasks, one pipeline stage per task.
- Region `europe-west1`. Secrets live in Secret Manager only. Model SDKs are called only from the backend.
- Never add: Redis, Postgres, Kubernetes, Kafka/RabbitMQ, microservices, LangChain/LangGraph, Redux.

## Code rules
- Simple code stays simple. No manager/factory/repository layers with one implementation. Interfaces exist only where there are real alternatives: `JobStore`/`FileStore`/`TaskQueue` (local vs Google Cloud) and `Provider` (Anthropic, OpenAI, Google Gemini).
- One source of truth for each business rule: pricing (`app/pricing`), state transitions (`app/jobs/state.py`), authorization (`app/core/auth.py`, `app/jobs/service.py`) and cost ceilings (`app/ai/costs.py`) live in the backend. The browser only displays server results.
- No `any` and no blanket `except`/`catch`. Catch an error only where you classify it, recover from it, or translate it at a boundary.
- Never log paper text, prompts containing paper text, secrets or signed URLs.
- Hide unfinished services through config. Never ship a control that only partly works.
- No placeholders in the product: no stand-in AI, fake results, invented prices or fake sign-in. What can't really work yet is shown as unavailable. Test stand-ins live only in `backend/tests/`.
- The roadmap for the intelligence layer is `PaperAid_Revised_AI_Algorithm_Claude_Context_and_Research_Architecture.md`, as amended by "Revised AI algorithm adopted" in `docs/decisions.md` (the amendments win).
- The Gemini workflow (owner decision 2026-10-07, `GEMINI_WORKFLOW`, on): every NEW engine routes each step (`STEPS`) to a stage in `app/ai/gemini.py` (`TASK_STAGES`): intake (Gemini 3.5 Flash-Lite, LOW thinking), planner (3.8 Flash, HIGH), research (3.8 Flash + Google Search, LOW), execution (3.8 Flash, MEDIUM), first audit (3.8 Flash, MEDIUM), second check (the AI check's independent second assessor, 3.5 Flash-Lite, MEDIUM), premium audit (3.1 Pro Preview, HIGH: the approval review of every deliverable), fix (3.8 Flash, MEDIUM) and final sign-off (3.8 Flash, MEDIUM). In a review → targeted repair → review loop (`AIRunner.audit_rounds`) the first round is the premium audit and every later round the final sign-off, which sees the earlier answers (`previousAudit`) and checks they were resolved (`signoff-v1`). Models and thinking levels are settings (`*_MODEL`, `*_THINKING`); a quote freezes routes, thinking, capabilities and the dated price record (`freeze_vertex`). Thinking counts against the output limit, so each step gets its level's room (`output_allowance`). Prices are Google's published Standard/Global rates (`app/ai/vertex_pricing.py`); a model without one cannot be used. Google Search grounding: every query charged at the rate above the shared free allowance; Google's redirect links in an answer are resolved to their pages and only those count as sources (`vertex.py`); extra queries are charged, never a failure. Engines priced before keep their OpenAI/Anthropic/Gemini-API routes, which run only with `LEGACY_PROVIDERS` on (off since 2026-10-07: such a step is refused before any spend, nothing charged). The Google SDK never retries (`NO_SDK_RETRY`: it would resend timed-out, possibly billed requests); PaperAid retries only 429/503 itself (`THROTTLE_ATTEMPTS`). Works drafts (2026-10-07) share one repair limit across section checks and the final review and stop when the final review repeats itself; a graph is given as data (`figure`) and drawn by code, a worked example is an `illustrative` table, both labelled by code (`w-draft-v4`, `w-repair-v5`); an example's numbers count only in its own cells and caption and in sentences that open as hypotheticals (`HYPOTHETICAL`), never in a factual claim. Each worker attempt owns its job (`lease_owner`): only the owner heartbeats, writes artifacts (attempt-scoped paths, read through `artifact_paths`), completes, fails or publishes.
- Earlier algorithm, for engines priced before 2026-10-07 and with `GEMINI_WORKFLOW=false`:
  One accountable final reviewer (owner decision 2026-09-30, superseding the dual veto): Luna and Sonnet independently assess every eligible passage; Luna, Sonnet and Gemini plan, draft, check integrity and repair; **Sol alone approves generated wording** (proposal plans and chapters, works plans, Results Models and documents, Paper Check rewrites), on the exact deliverable, after bounded targeted repair (at most two rounds, each reviewed again). Sol never approves what it finalised: proposal-plan, profile and spec finalisation are Sonnet's. Opus gives optional advisory guidance (`FRONTIER_GUIDANCE`, off by default), never a veto. A review that is missing, cut off, refused or unaffordable is "not reviewed", never approval. Frozen older jobs keep their quoted roles (`Engine.single_reviewer` False: both approvals). Routing is shared by execution and pricing in `app/ai/orchestration.py`.
- Works (concept notes, coursework, funding proposals; owner decision 2026-09-30) use worker → evaluator → repair with roles set in configuration (`role_models`): analyst and integrity checker Luna, writer Gemini 3.8 Flash, section evaluator Sonnet, **final reviewer Sol** (`FINAL`), optional adjudicator. Code checks win over any model score; only failing sections are repaired, at most `repair_attempts` rounds. Sol's final review sees the exact deliverable (paragraphs, section and generated tables, references, notes) and must give a verdict for every rule, question part and priority, in parts with a manifest for long documents. Each quote freezes roles, tier, the dated price table and content hashes (`work_engine`). A plan or Results Model Sol does not approve is kept, not charged, and approved only with the student's recorded acknowledgment; a document with an unresolved PaperAid-owned blocking defect fails without charge.
- Rules for works are data (`app/rules/data/*.json`, rulebook v1.0 as amended in `docs/decisions.md`); validators are code (`app/rules/validators.py`); what applies is resolved in one place (`app/rules/resolve.py`). Released rule files never change (`app/rules/data/released.json`).
- Code measures, models judge: writing signals are versioned rules in `app/analysis/rules.py` (signals-v2); both checkers confirm or reject them in context. Omission is not LOW. Incomplete coverage has no overall percentage; a low-against-high disagreement is shown as uncertainty and lowers confidence; thresholds remain uncalibrated. Approved text is delivered exactly as approved. Nothing is rewritten only because a threshold was crossed. Citation checks (`app/analysis/paper_checks.py`) are separate from AI-likeness. Model inputs stay deterministic so paid estimate answers replay.
- Released prompts never change (`app/ai/prompts/released.json`, enforced by a test): add the next version and point `STEPS` at it. Each job runs with the engine it was priced with.
- Speed without touching the work (owner, 2026-10-08): every Gemini call of a job stage holds a slot of one shared limit (`app/jobs/capacity.py`, Firestore `capacity/`, `capacity_*` settings); no slot within `capacity_wait_sec` pauses the stage (`CapacityWait`: work kept, no retry used, uncharged stop after `capacity_max_waits`); the limiter failing pauses, never bypasses. Research runs `research_parallel` topics at a time in topic order, each finished topic saved (`checkpointed`). A lost search is asked once more; a topic lost in two runs of its stage (`LOST_TOPIC_RUNS`, four tries) is left out and named in the document's checks (`research_gaps`, `W-RESEARCH`/`C{n}-RESEARCH`), never dropped silently, and too many requests never counts as lost; research is never cut short by time. A call takes a slot of its model and a search one of the model's search slots as well; calls of one job wait for each other's real cost before saying the budget is spent (`_settled`).
- Algorithm revision (owner, 2026-10-09; `WORKFLOW`, 1 until a trial proves 2; frozen per engine as `Engine.workflow`, read `docs/decisions.md`). Workflow 2, research: topics carry a category, `essential` and `coveredBy` (`w-needs-v2`/`p-needs-v2`, stage `topics`); studies and methods are read first from the scholarly index (a ranked pool of `index_candidates`, the best `index_abstracts`; PaperAid's key `OPENALEX_API_KEY`, sent only to api.openalex.org, never logged), official figures and policy from the web, the other route only when the first could not be asked or an essential topic is unanswered (`gather`, `TopicRoute`); an essential topic with no evidence stops the step uncharged (`EVIDENCE_MISSING`). Workflow 2, approval: the final editor (stage `final_editor`, Gemini 3.1 Pro, HIGH, never a fallback) reads the finished work once, corrects it by paragraph (`w_edit`/`p_edit`, applied by `apply_corrections`; a correction to an unknown place is refused) and decides; code checks the corrected text and a standard check may only flag a corrected claim (`w_flag`/`p_flag`); only then one more look (`w_resolve`/`p_resolve`); wording code still cannot trace is never released; no writer rewrites after the editor (before it the writer develops a draft well under its limit and compresses one over it). When the editor's model cannot answer the stage waits with its work kept (`CapacityWait` kind REVIEW, `review_wait_sec`); its share of the cap is kept from the first stage (`keep_for_editor`); a coursework plan is decided by code checks (`CODE_CHECKS`); the decision is recorded with hashes (`Approval`, admins only) and a work's Word file is read back before it is published (`export.verify`). For every workflow: a call waiting for the budget holds no slot, and waits for capacity are bounded by time (`capacity_wait_limit_sec`).
- Keep the app runnable after every change: `cd web && npm run dev` must keep working.

## Domain vocabulary
- Job `status`: DRAFT → QUOTED → (AWAITING_PAYMENT) → QUEUED → PROCESSING → COMPLETED | FAILED | CANCELLED.
- `stage`, used only while PROCESSING: EXTRACTING, ANALYSING, RESEARCHING (source check, proposal research), PLANNING, REFINING, REDRAFTING, DRAFTING (proposal chapters), AUDITING, FORMATTING, CONVERTING (LaTeX), EXPORTING.
- `paymentStatus` is separate: NOT_REQUIRED, PENDING (credits held), PAID, FAILED, REFUNDED.
- Students see **credits** (owner decisions 2026-09-28 and 2026-10-01, renamed from tokens): 1 credit = `ugx_per_token` (UGX 1,000), shown to one decimal; UGX appears only where credits are bought. No price line on Start: the balance and anything reserved show in the top bar; `min_credits` sets each service's minimum balance; one Start bundles the read and plan into the first document's price (`ServiceSelection.bundled`). The ledger stays in exact UGX. Prices are fixed per service and page band (`pricing_mode="fixed"`, `fixed_tokens`, version `fixed-v1`); the quote's `budget_usd` caps what the job may spend, and settlement charges each line by what was delivered, never more than quoted. `pricing_mode="cost"` (actual AI spend × `price_multiplier`) remains for tests. Rules: `app/pricing/` (`quote.py` formulas, `credits.py` ledger and `tokens()` wording, `billing.py` hold/settle/refund). Balances only move inside `update_job_and_wallet` (or, for proposal steps, `update_job_wallet_and_project`) transactions.
- Student-facing text says what PaperAid does, never how (owner decision 2026-09-28): no model roles, advisers, second AIs, algorithms, or the institution's manual and section numbers. Those stay in code, prompts, the rulebook and admin views.
- A COMPLETED job with `outcome: "PARTIAL"` must show its warnings. It is never presented as a clean success.
- Research proposals (`app/proposals/`, owner decision 2026-09-28): a persistent **project** (plan, chapter versions, evidence library) whose paid steps are ordinary jobs linked by `projectId`. The rulebook is data from the UCU handbook, which takes precedence (`app/proposals/rulebooks/ucu-2018-v2.json`, the default since 2026-10-08; v1 for proposals under way): the general objective under Objectives with the specific ones, a primary research question, null and alternative hypotheses, all placed by code from the approved plan word for word (`from_plan`, `plan_statements`) and checked before a complete export. The owner's one exception: Bachelor's, PGD and Master's take three specific objectives, four only when the student asks (`objectives_by_level`, `four_objectives`); research questions avoid the past tense unless necessary. Approved decisions have ids and hashes (`decisions.py`); a changed decision marks the sections built on it for review. Writers cite only by evidence token; code renders APA 6/7 and removes any citation or figure it cannot trace (`evidence.py`). Sample sizes come from `sampling.py` and the student's own figures, never a model. Readiness is a checklist (PASS / NEEDS_REVIEW / MISSING / NOT_APPLICABLE / BLOCKED, each CODE / AI / AUTHOR), never a mark.
- The AI checker is hidden (owner decision 2026-10-07, `AI_CHECK_ENABLED` off) until a validated detector is integrated; Paper Check starts at Redraft. When shown, students get writing-pattern feedback only (owner decision 2026-09-30, after a real-model pilot scored 10 human and 10 AI-written papers alike): passages marked as generic, formulaic or repetitive with reasons and suggestions, and nothing that claims to detect AI or judge authorship. The AI-likeness percentage and band are still computed (word-weighted, rounded down into their band) and kept for admins and calibration; `SHOW_AI_SCORE` shows them again only once a validated detector exists.
- Works (`app/works/`): a persistent record in its own `works` collection whose paid steps (READ, PLAN, DRAFT, REVISE) are ordinary jobs linked by `workId`. The student confirms what PaperAid understood (requirements with their quotes, questions, conflicts, eligibility) before planning; funding proposals have a Results Model (the one source of the logframe, workplan and M&E table) and a budget whose sums are all code. Coursework takes no files at Start (owner decision 2026-10-08): the question is typed and the question paper pasted (saved as the `BRIEF`); a request to PaperAid ("Solve this assignment for me?") is never the question (`resolve.is_request`). Nothing about AI is asked or printed: the last-page note "This document was drafted by an AI-assisted third party." is added only when the student asks (`ai_note_asked`), and an assignment whose text bans AI tools is told to the student on screen (`AI_BANNED_NOTICE`), never in the document; there is no detector-evasion step. An academic concept note is a proposal project with `goal: "CONCEPT"`, which never starts Chapter One.
- One Start (owner decision 2026-10-01, `docs/decisions.md`): coursework, concept notes, funding proposals and research proposals start from two pages (`/app/start/...`) and open in a workspace; the plan stays internal and continues only when PaperAid's own final review and code checks approve it (`continue_after_plan`), otherwise it stops without charge. Funding figures only the applicant gives are drafted as marked gaps and filled in afterwards without AI (`POST /works/{id}/figures`). Works and proposals set up before keep their earlier pages until written. A proposal Start needs only the student's name (2026-10-08): what is left blank PaperAid proposes and shows as proposed until confirmed (`proposed`, `POST /projects/{id}/setting`); assumed sample settings never stop it (confirmed in Chapter Three); an institution guide read after chapters exist restructures them by code, each as a new version (`align_document`, `to_align`). The conceptual framework is black and white by default, draws every variable (a concept framework for a qualitative study) and is edited from the workspace (`POST /projects/{id}/framework`).
- One screen from upload to final draft for Paper Check (owner decision 2026-09-29): uploading opens the paper on its job page with only the next step beside it (Check for AI, Redraft or Format); options appear only for the step chosen; results, Redraft, Ask for changes (the student's own words reach the writer), Check my sources and Format continue from the same paper (`POST /jobs/{id}/continue`). Chapters and the concept paper take Ask for changes too.
- Three sections (owner decision 2026-09-29): Paper Check (check → redraft light/standard/deep → review changes → finish), Research Proposals, Academic Formatting. Source check, university templates and LaTeX are steps or finishing choices inside them, never jobs of their own (`SECTIONS` in `web/src/lib/services.ts`); older `?service=` links open their section.
- Data Lab (`app/datalab/`, owner decisions 2026-10-03/04): its own section and `datalab` collection. One engine (`engine/`: ingest, profile, clean, stats, disclosure, filters, charts, maps) serves Data Lab and Chapter Four. Data work runs in the worker (`dop_` tasks, one per project at a time); files get names of their own and are deleted only after the record changed; every analysis carries a fingerprint and a changed one marks it out of date. Code calculates, models explain (number tokens; R reference tests). Small counts and any total or test number that would reveal one are hidden (`disclosure.protect`, audited by linear programming); filters keep at least the threshold and leave out none or at least it, and results released together are checked as a set. The final review reads the assembled document and the approved one is exported. Coordinates and identifiers are left out by default; uploads need accepted terms and two recorded confirmations; countries fail closed (`countries.json`: only Uganda). Maps: UBOS districts, subcounties (always with their district), sub-regions, regions; released layers are frozen by hash. The report's tiers need owner prices. Private mode (browser) is measured and not built. Two sections, one page each (2026-10-04): quantitative and qualitative; qualitative projects (`qual.py`) keep transcripts only after listed names and contact details are replaced, code keeps a quote only if it is in its transcript word for word, and deliver a themes report and an Excel codebook (QL prices are the owner's).
- Billing guards (owner decision 2026-09-29): an AI Check that cannot produce a complete result is not charged (`delivery["AI_CHECK"] = 0`); a paper with nothing scorable is refused before pricing (`NOT_SCORABLE`); unapproved university rules are skipped and that line refunded; with `PARTIAL_CHAPTERS` on (off by default, owner decision 2026-09-30) a new chapter delivers only approved sections, charged by their share, and "Finish chapter" (API step `COMPLETE_n`, stored as the chapter step with `finish=True` so older releases can read it) writes the rest, capped at what the chapter has not yet cost (`ChapterDocument.full_price`/`paid`). A proposal step runs and publishes only on the guide and structure it was priced on.

## Commands
- Everything: `start-paperaid.bat`. Backend on :8000, web on http://localhost:5000.
- Backend tests: `cd backend && .venv/Scripts/python -m pytest -q`; lint: `.venv/Scripts/python -m ruff check app tests`.
- Web: `cd web && npm test` (unit tests), `npm run build` (typecheck + build); `node scripts/e2e.mjs out` (and `node scripts/e2e-start.mjs out` for one Start, `node scripts/e2e-proposal.mjs out [proposal.docx]`, `node scripts/e2e-works.mjs out` for the earlier pages, `node scripts/e2e-datalab.mjs out` for Data Lab) runs the browser journey against web on :5000 and the browser-test backend (`cd backend && .venv/Scripts/python -m tests.serve_e2e`).
- Test documents: `backend/tests/fixtures/generate.py` regenerates the 28 fixtures; `manifest.json` records what each must do.
- Read-only tools: `backend/inspect_ai_score.py JOB_ID` (one job's scoring), `backend/cost_report.py [--local DIR] --since DATE` (AI spend against price, failed and abandoned work included). `backend/speed_report.py [--local DIR] --since DATE` (time per task and stage, slot waits, timeouts, first-try and eventual completion). `backend/calibrate.py FOLDER --budget-usd N` makes paid calls: it compares score formulas on labelled papers (a development half chooses, a test half reports).
- Load test: `cd backend && .venv/Scripts/python -m tests.load_test --students 40` against a dev-auth backend (no AI is called).
- On Windows, give pytest a short `--basetemp` (for example `C:/Users/USER/AppData/Local/Temp/pt`): long temp paths pass the 260-character limit.
