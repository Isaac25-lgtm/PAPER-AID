# PaperAid production audit and engineering handoff

- **Date** 15 November 2026, Kampala
- **Source** `main` at `aa45b8d0f`, matching the local `origin/main` reference
- **Production** [PaperAid](https://paperaid-ca172.web.app/app)

## Release decision

**Keep the current invite-only AI pilot.** The public app, API and worker are running. Data Lab is absent from the live API and catalog, the Word/PDF dependency pins now pass the Python advisory check, and GitHub CI is green on both the backend release and the dashboard tip. The dashboard and retained workflows ran in the local browser with synthetic data. Night mode still has three measurable contrast failures, a public sign-in theme leak and a modal keyboard-focus defect. Lowering the upload word limit can also block access to an already accepted Word file.

Broad rollout and payments need a demonstrated AI spend stop, administrator MFA, recovery of records and files together, and measured job delivery under load. This audit reviewed the current code across the retained application surfaces, retested the release changes and checked production configuration and logs read-only. It made no production writes or provider calls. The signed-in journeys used local model stand-ins. The preceding audit remains a historical baseline for the October release.

## 1. Dashboard and night mode

The review covered the greeting and Continue writing, the New page and section navigation, Paper Check results and changes, proposal chapter tables and framework figures, student and admin credits, the Operations and Reliability pages, and the account-deletion dialog. I inspected a populated dashboard, admin queue and student ledger as well as proposal and Paper Check content in Chromium with synthetic data. The dashboard, student credits, Operations and Reliability showed no page-level horizontal overflow at 390 pixels. Contrast was measured from computed colours for the source class pairs. The WCAG AA minimum for these ordinary-size labels is 4.5:1. [WCAG 2.2 contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

| Checked pair | Night ratio | Result |
|---|---:|---|
| `text-fg-subtle` on `surface-subtle` | 5.52:1 | Pass |
| `text-fg-subtle` on `surface-muted` | 4.86:1 | Pass in night mode. Day mode is 4.39:1 for the same pair. Check actual small-text uses before changing the shared token. |
| Neutral, Ready, Queued, warning, Failed, Processing badges | 7.82–12.63:1 | Pass for all six shared status chip pairs |
| Primary button white on brand fill | 4.79:1 | Pass at rest |
| Success alert dark green text on green fill | 1.59:1 | Fail. The shared alert uses `emerald-900`, which has no night override. |
| Destructive button white on red fill | 2.65:1 at rest, 1.90:1 on hover | Fail. Measured on the enabled account-deletion button. The generic danger button pairs fixed white with red shades remapped for dark-theme foreground use. |
| Selected Paper Check strength option | 1.16:1 | Fail. The selected pill uses white lettering on the near-white night foreground token. |

**P2 · Fix the three contrast failures in the shared controls.** Separate colours for solid fills and their text from palette shades used as text on dark surfaces. Style the selected Paper Check option with an accessible pair. Test both themes, active and hover states, and an enabled destructive confirmation. The sampled status chips and muted-on-subtle text can retain their night values. [Alert and badge](../web/src/components/ui/primitives.tsx#L9), [danger button](../web/src/components/ui/button.tsx#L11), [Paper Check strength](../web/src/features/results/workspace.tsx#L358), [night palette](../web/src/styles/globals.css#L56).

**P2 · Clear the initial night theme when a protected route redirects to sign-in.** In a fresh signed-out context with a stored Dark preference, visiting `/app` leaves `data-theme="dark"` after the router redirects to `/sign-in`. A direct load of `/sign-in` under the same preference has no theme attribute. This occurred both locally and on Hosting. The initial HTML script applies the theme, and the signed-out route never mounts the app layout that would clear it. Add a regression for a signed-out deep link, signed-in reload and sign-out. Keep the preferred first paint on authenticated app routes. [First-paint script](../web/index.html#L26), [auth redirect](../web/src/features/auth/auth-pages.tsx#L26), [theme hook](../web/src/lib/theme.ts#L30).

**P2 · Restore modal keyboard focus.** The account-deletion dialog opens correctly and Escape dismisses it. In the browser check, focus returned to the document body instead of the button that opened it. The shared portal wrapper has no associated trigger or explicit focus restoration. Test Escape and Cancel with the keyboard and verify focus returns to the invoking control. The backdrop also uses `bg-fg/40`, which becomes a light veil at night. Use a dedicated scrim colour to keep focus on the dialog. [Dialog and drawer](../web/src/components/ui/overlays.tsx#L17), [account confirmation](../web/src/features/account/settings-page.tsx#L76), [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

**P3 · Keep exported figures readable in the app.** Proposal document tables use themed surfaces and text. The framework PNG retains its document background and preserves its own text contrast. Its surrounding border is fixed `#ddd`; a theme border will match the other night-mode surfaces. Preserve the underlying downloaded graphic. ## 2. Stored Word files and parser limits

**P2 · Apply the current word limit at admission and preserve access to accepted files.** I uploaded a 300-word synthetic DOCX with a limit of 400. Preview succeeded. With the same stored job and the limit reduced to 100, preview and selected-passage pricing both returned `DOCUMENT_TOO_LONG`. A new upload under the lower limit also returned `DOCUMENT_TOO_LONG`, as intended. The existing stored-file regression currently asserts rejection for any stored file over the limit passed to the helper. [Bounded DOCX intake](../backend/app/documents/intake.py#L89), [stored preview](../backend/app/jobs/workspace.py#L54), [selected-passage quote](../backend/app/jobs/service.py#L530), [current regression](../backend/tests/test_datalab_removed_20261115.py#L59).

Use the accepted immutable file and its accepted metadata for read and rebuild paths. Avoid reapplying the current admission word limit when an owner opens previously accepted content. Retain the timed child process, single-parser slot and Linux CPU and memory limits. For new quotes and continuations, enforce the current rules before creating a hold. Preserve the accepted input and applicable limits for already submitted work. The worker verifies the source SHA, then currently applies the latest upload settings again, so a policy change can still break an existing queued quote after a preview fix. Add tests for preview, rebuild, a new quote and an already accepted job across a cap change. [Worker extraction](../backend/app/jobs/pipeline.py#L308), [continuation admission](../backend/app/jobs/workspace.py#L214).

**P2 · Measure the remaining synchronous rebuild path.** The direct stored-source rereads moved to the bounded parser. Two rebuild layout branches still call `read_docx(paper)` on intermediate bytes, and some export formats invoke a renderer while the API request is open. Those inputs pass earlier validation. Under concurrent rebuilds the work still shares the API's process memory and 120-second request envelope. Test valid maximum-size papers with concurrent preview, rebuild, exports and ordinary reads. Reuse a proven parsed model or apply the same parser boundary where the test or code warrants it. [Rebuild layout](../backend/app/jobs/workspace.py#L174), [proposal exports](../backend/app/api/projects.py#L179), [renderer](../backend/app/works/render.py#L20).
